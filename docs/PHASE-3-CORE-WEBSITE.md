# ThreatFade Web — Phase 3 Core Website

Phase 3 establishes the primary product experience around verified engine capabilities.

## Core routes

- `/` — product overview and multi-audience conversion paths
- `/product` — product model and evaluation paths
- `/detection` — detection methodology and supported scenarios
- `/how-it-works` — operational and technical flow
- `/integrations` — current interoperability surface
- `/security` — engineering controls and assurance boundary

## Conversion paths

- Developers: Discover → Understand → GitHub → Run → Contribute
- Researchers: Discover → Research → Methodology → Evidence → GitHub
- SOC teams: Discover → Detection → Evidence → Playground
- Enterprise: Discover → Architecture → Security → Deployment → Contact

## Claim discipline

All public product language is constrained by the engine README and current implementation. Project validation is explicitly separated from independent assurance. The interactive behavioral lab is clearly labeled as illustrative telemetry, not a live detection result.

## UX principles

- Evidence before decoration.
- Technical language before marketing euphemism.
- GitHub is a first-class developer destination.
- Existing security operations systems are complemented rather than displaced.
- Interactive visualization is used only where it improves comprehension.
- Mobile navigation remains discoverable without requiring client-side application state.
