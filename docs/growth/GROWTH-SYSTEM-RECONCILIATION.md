## Critical findings requiring implementation

1. **Duplicate semantic lead events:** `LeadCaptureForm` currently emits the same request event on form start and again after success. The start emission is removed in the reconciliation branch so the request event means a successful accepted request only.
2. **Attribution gap:** campaign IDs were not captured from landing URLs. The tracker is extended to preserve `campaign_id` with the first-touch attribution record.
3. **Playground instrumentation gap:** scenario selection did not emit genuine `playground_start` / `playground_complete` events. These are added around the real API request.
4. **Customer lifecycle truth boundary:** the website must not fabricate first detection, repeat usage, retention, NRR, or contract state. These remain explicit engine/product/CRM/billing dependencies.
5. **Analytics durability boundary:** the current API validates and rate-limits events but cannot guarantee global idempotency in a stateless/serverless runtime. Durable deduplication remains a provider/platform responsibility.

## Release rule

The final audit may only mark a requirement `IMPLEMENTED` when the code path and test evidence exist. External provider capabilities must remain `EXTERNAL_DEPENDENCY` until the actual integration and provider acceptance test exist. Unmeasured production behavior must remain `UNVERIFIED` rather than being inferred from code inspection.
